# AGENTS.md

Guidance for coding agents working in this repository.

## Project

Parametric, 3D-printable wearable charms for the Italian Consulting team at Red Hat's RH1 2027 (Las Vegas, January 2027): a name tag (`consulting@italy:~$` between a green and a red band), a tricolour moka pot, and a moka that pours (`services` along the stream from its spout), each with an eyelet, magnets (plus a counter plate worn inside the shirt) or, for the tag and the moka that pours, a lanyard clip. The Python package and command are `rh1charms`. It follows the owner's earlier project `/workspace/3d-linux` (github.com/amedeos/3d-linux), from which `params.py`, most of `relief.py`, `export.py`, `slicer.py` and `render.py` come.

- **Printer:** Prusa MK4 (Input Shaper firmware) with **one extruder**: no MMU, no INDX. Colours come only from M600 colour changes by layer height.
- **Slicer profile:** PrusaSlicer "Original Prusa MK4 Input Shaper 0.4 nozzle", "0.20mm STRUCTURAL @MK4IS 0.4", "Prusament PETG @PGIS". 0.2 mm layers (first layer too), 0.45 mm lines. **No supports.**
- **Material:** **Prusament PETG only**, in white, red, green and black (`filaments.FILAMENTS`). Do not add other colours or materials without asking.
- **License:** CC BY-SA 4.0. The font keeps the SIL OFL 1.1.
- **Trademarks:** Red Hat and RH1 are trademarks of Red Hat, Inc. **Never use the Red Hat logo anywhere** (models, renders, docs).

## Environment and commands

- Python 3.14 (3.13 also works), [uv](https://docs.astral.sh/uv/), [build123d](https://github.com/gumyr/build123d) 0.13, fontTools, shapely 2.

```sh
uv sync
uv run pytest                  # ~3 min
uv run ruff check
uv run rh1charms list
uv run rh1charms export [CHARM|tag|moka ...] [--wear W] [--layout L] [--copies N] [--set key=value]
uv run rh1charms slice         # optional, PrusaSlicer CLI
uv run rh1charms render [CHARM|tag|moka ...]
```

- The modules also run on their own: `python -m rh1charms.slicer|render` (render takes the same names and options as the command).
- The output is `out/stl/`, `out/3mf/` (plates and `plan.json`: each plate's start filament, colour changes and bridges), `out/3mf/projects/` and `out/render/`.
- PrusaSlicer may have no data directory on a headless machine ("Configuration wasn't found"). Make a folder with `vendor/PrusaResearch.ini` (copied from `/usr/share/PrusaSlicer/profiles/`) and a `PrusaSlicer.ini` with `[presets]` (the three profile names) and `[vendor:PrusaResearch]` / `model:MK4IS = 0.4`, then run `PRUSA_SLICER="prusa-slicer --datadir <folder>" uv run rh1charms slice`.

| `filaments.py` | The four filaments (name → hex) and the PrusaSlicer material profile |

| `text.py` | Glyph outlines with fontTools (curves flattened, nonzero fill rule evaluated exactly with winding numbers), line layout (monospace grid, `two_lines` split), a line bent along a circle (`arc_text()`), the smallest font size (`limits()`, `arc_limits()`), `size_problems()` |
| `charms.py` | `Charm` (frozen dataclass): subject, wear, layout and every parameter; `LAYOUTS_OF`, `drawing()` (tag, moka, moka_pour: each with its `DEFAULT_BANDS`, `COLOURS`, `DEFAULT_WEARS`), `band_ts`; `VARIANTS` (the 11 defaults); `charm(name, **overrides)`, `parse_name()`, `parse_value()`, `validate()` |

| `relief.py` | Regions → printable bands (`colour_bands`, as in 3d-linux) → build123d solids (`slab`, `stack`, `fuse`, GRID and INSET) |
| `wear.py` | `layout()`: the eyelet tab, the magnet pockets or the clip (on a backing plate if the drawing needs one), band 0 as stacked slabs (`slabs0`), the centre of mass; `band_z`, `colour_changes`, `bridges`; the solids (`band_parts`, `make_charm`, `coloured`, `mass_centre`) |
| `magnets.py` | Counter plates, the pocket gauge and the clip gauge (for a clip without a backing plate); `extras()`, the single-colour parts a list of charms needs (export and render both use it) |

| `slicer.py` | Optional PrusaSlicer CLI run: time and filament, M600 check (heights and colours) against `plan.json`, a second slice with automatic supports that must create none, a bridge check at every height `plan.json` lists, projects with the full config and the start filament as the filament colour |
| `render.py` | numpy z-buffer renderer (no OpenGL, from 3d-linux); `charm_images()` (front, back, edge, flat, hang), `plate_images()`, `all_images()`; `mask()` rasterises a geometry (also used by the tests) |
| `__init__.py` | The `rh1charms` command; `select()` turns names and `--wear`/`--layout` into charm names. Every charm is laid out before a command writes anything. `slice` takes no names or options. `python -m rh1charms.render` runs `rh1charms render` |
| `tests/` | pytest suite. Keep it green. |

## How a charm is built

- **Bands.** `bands[0]` (white) prints the whole body. Band k (k ≥ 1) covers every region whose colour is band k or higher, so the bands are nested: nothing hangs in the air. Band k starts on top of the bands below it: `base_t` plus their thicknesses (`Charm.band_ts`: `band_t`, but `red_t` for red; `red_t` 0 means `band_t`, or `POUR_RED_T` = 1.2 mm on the moka that pours). Its M600 is at `layer_top()` of that height. A region in white (the moka's waist and facet grooves) shows at the top of the body. `validate()` wants every colour of the drawing among the bands, and no band above the last of them: it would be empty (a colour change for nothing). An unused colour lower in the stack is allowed: its band covers the colours above it. Under a green or black region, the bands below show as stripes on its side walls: one extruder colours by Z only.
- **Numbers.** `Charm.validate()` refuses nan and inf (they pass every comparison), and `on_grid()` allows only floating-point noise (1e-6): a thickness a hair off the grid would move the next M600 one layer late.
- **Cleanup in 2D, not in OCCT.** All booleans run in shapely. `relief.colour_bands` comes from 3d-linux unchanged: it opens every band by `MIN_STROKE / 2`, widens or fills gaps narrower than `MIN_GAP` and fills hairline cracks. It **repairs silently**, so anything that must hold exactly (the text) is checked before it runs.
- **The font size (`text.py`).** Font size = em size in mm. The glyphs scale linearly, so the text is measured once at one em. `narrowest()` finds the largest closing radius (the narrowest gap) and the largest opening radius (the thinnest stroke) that keep the topology: the number of pieces and holes. A wider closing would join two strokes or seal a counter; a wider opening would break a stroke or remove a piece. Crotches and stroke tips do not change the topology: every size has them, and the printer only rounds them. The size is the smallest one, rounded up to 0.1 mm, with gap ≥ `MIN_GAP` and stroke ≥ `MIN_STROKE`. For `consulting@italy:~$` it is 8.3 mm, set by the slot between the stem and the ring of the `@` (0.0548 em); `$` alone would allow 6.5 mm. A forced `font_size` below that raises an error in `artwork.tag()`, before `colour_bands`. The topology misses one kind of stroke: one that vanishes without changing it (the foot of an `L`, the bar of a `T` or a `7`). So `wear._artwork_and_bands` also checks, for every text, that the letters come through `colour_bands` unchanged but for their corners (`text_damage`: the same pieces and holes one for one (`same_features`: each piece and hole of the raw text holds one of the raised text, and nothing lies elsewhere, so a counter that fills and a gap that closes cannot cancel out), no lost piece over `LOST_MAX`, at most `LOST_SHARE` of the area, no filled gap over `SPECK`; a lost piece thinner than 2 × `SLIVER` everywhere is a sliver shaved off a long outline, and only `LOST_SHARE` counts it). An automatic size goes up 0.1 mm at a time until they do (`LT`: 2.1 → 5.1 mm; `Artwork.size_bound` says why); a forced size that fails is an error. `tests/test_text.py` checks the size with a second, independent measure on pixels, and the letters of the default and of such texts after the cleanup. `narrowest()` compares signatures, not counts: every piece and hole of the morphed text is matched to the piece or hole of the text it lies in, so a hole that closes cannot hide one that opens elsewhere (`~$ espresso`: 6.8 mm, not 5.5).
- **The tag.** A rounded rectangle (`CORNER`), with full-bleed `END_BAND` bands (green left, red right) and the red text in the white middle, `TEXT_MARGIN` from the bands and the edges. Its size follows from the text. `two_lines` splits before the last `@` or at `\n`; the lines are left-aligned, `LINE_PITCH` em apart.
- **The moka.** The polygons in `artwork.py` as given (origin at the bottom centre, y up), painted in order (a later part covers an earlier one). The facet grooves are cut down to white. The body is the union, 0.9 mm larger, with its holes under `WINDOW_MIN` (4 mm²) filled. **The handle comes clockwise**: `relief._faces` turns every outline counter-clockwise, and every extrude still passes `dir=(0, 0, 1)`.
- **The moka that pours** (layout `pour`, `drawing()` = `moka_pour`). The moka is mirrored (spout on the right, so the text reads away from it) and leant `POUR_TILT` (35°) clockwise (`pour_pose`). The stream leaves the tip of the spout along its axis and bends clockwise on a circle: `STREAM_RADIUS` at least, and large enough that an arc of its middle line as long as the lead and the text turns at most `STREAM_TURN` (60°); the letters lie on a smaller radius (their baseline) and turn a few degrees more, 64° for `services` (`stream_layout`). The text (`arc_text`) starts `STREAM_END` from the tip and moves along the stream, `LEAD_STEP` at a time, until it is `STREAM_CLEAR` from the pot; the stream goes on `STREAM_END` after the last letter, then ends round (its ends are half-discs). The stream is painted first, under the pot. Its width is the text's height plus `STREAM_MARGIN` on each side. Knob and handle are red: no black band. The bent text draws its glyphs' bottoms together: Only the bent line is printed, so only its limits count: `smallest_size` starts at the glyphs' own limits (`glyph_limits`: the bend keeps each glyph's shape) and goes up until `arc_limits` pass (the bent line, measured in em at the stream's radius over the size, before the lead moves the text: on the safe side). For `services` that is 6.8 mm (the gap in `e`); the straight line would need 7.9. The automatic size is at least `POUR_FONT` (10 mm, `auto_size`). A size under the bent line's limits on its own stream raises `artwork.TooSmall`: for a forced size it is the error, for an automatic one `wear._artwork_and_bands` tries the next step (a short stream bends tighter as the letters grow). The plain moka has no text and ignores one, so a `--set text` for every charm works. `text_damage` reads `parts["text_zone"]`: the stream, 0.5 mm in, clear of the pot (the spout, lid, knob and handle are red too). `Artwork.plate` says that a clip needs a backing plate. The plain moka (no text) is unchanged, byte for byte.
- **Eyelet.** A tab (`tab_r`, 4 mm) with a `hole_d` (4 mm) hole: a 2.0 mm ring. Band 0 only. It sits on the highest point of the body under it, and `_settle` finds where the hole is over the centre of mass (from the 2D slabs; `test_wear.py` checks it on the solids). `_settle` uses the secant method: what it places moves the centre of mass, for a wide clip channel the other way and almost as far, and a plain repetition of x = centre of mass then swings from side to side.
- **Magnets.** The body is `MAGNET_BODY_T` = 2.8 mm: pockets `POCKET_DEPTH` = 2.2 mm deep from the bed, under a `ROOF_T` = 0.6 mm bridged roof. The pocket diameter is `MAGNET_D + magnet_clr`; the clearance never changes the depth or the roof (the grid). The tag has two pockets at a quarter of its width from each end, the moka one at the chamber's centroid height, on the centre of mass. The moka that pours has two, in the middle of the upper chamber and of the boiler (both inside their part): its centre of mass lies on the stream, too narrow for a pocket; its counter plate is a capsule. Every pocket keeps `MIN_POCKET_WALL`. The counter plate (`COUNTER_T` = 3.0 mm, `COUNTER_FLOOR` = 0.8 mm, pockets open on top) has the charm's pockets mirrored. The pocket gauge prints its pockets like the charm's (bed side, same roof): it measures the first layer's squish.
- **Clip (owner's choice: solid to the bed).** The spec put the tag at z = 2.8 on two risers, which left about 40 mm of tag unsupported on each side of the channel. So, outside the channel, the body goes down to the bed and its walls are the risers (at least `RISER_W`). Band 0 is three slabs: the floor (walls + bar, 0–1.2 mm), the walls (1.2–2.8), the whole body (2.8–4.0). The bar (`BAR_W` × `BAR_T`) joins the left wall (`OVERLAP`) and stops `SLIT` before the right one. The channel (`lanyard_w + CHANNEL_EXTRA`) runs across the whole height of the tag and lies over the centre of mass; if the walls at the ends of the tag stop it short of that (a lanyard almost as wide as the tag), it is an error, not a tag that hangs crooked. The check that a charm is too narrow is geometric (`_strips`: the widest rectangle `BAR_W` high inside the body), so the plain moka fails with the widths, not because of its name. `wear.clip_slabs()` builds band 0 of a clip. The clip gauge (`magnets.clip_gauge_layout`) uses it too: four separate pieces, each the back of the first clip charm (its channel, bar height and body height), with only the slit changed (`CLIP_GAUGE_SLITS`, 1 to 4 dots). `SLIT` is a constant, not a `Charm` parameter: the owner chooses it from the gauge. **The backing plate** (the moka that pours, `_plate_clip`, `plate_for`): a `rounded_rect` exactly the channel and its two walls wide (26.8 mm, so the walls are `RISER_W` but in its `PLATE_CORNER` corners), `PLATE_MARGIN` above and below the body inside that strip, and at least `PLATE_MIN_H` tall (27 mm: two bars `PLATE_EDGE` from its edges, `BAR_W` between them), grown around the strip; band 0 is `opening()` of the body and the plate, as `colour_bands` makes it, with its holes under `WINDOW_MIN` filled (where the plate meets the outline, a small pocket can close into a hole that would go through the whole clip). The plate and the channel move together, and `_settle` puts them over the centre of mass. Two bars, `PLATE_EDGE` from the plate's top and bottom: the top one joins the left wall (`SLIT`), the bottom one the right wall (`SLIT_WIDE` = 1.5 mm, from a two-bar gauge: with 1.1 on both, the ribbon had to turn on its edge again between the bars). `Clip.bars` lists them, top first; `Clip.plate` is the plate. A clip on a plate has no clip gauge.
- **Plates.** One variant per plate (one M600 schedule): `--copies` copies in a grid centred on the bed (`GAP`). A magnet charm adds its counter plate (the same copies) and the pocket gauge (once); a clip charm without a backing plate adds the clip gauge (once). The gauges are `export.GAUGES` (their bridges, and how many bodies: the clip gauge has four, `export.bodies()`). Every plate is laid out before anything is written; too many copies is an error with the largest number. `plan.json` holds each plate's `start`, `changes` and `bridges`.

## Frames

- **2D:** x along the charm (centred on the tag; the moka's boiler centre at x = 0), y up as worn. The tag's bottom edge is at y = 0; the moka's boiler bottom is at y = 0, its body reaches y = -0.9.
- **Print pose:** the same x and y on the bed, the front face up (+z), z = 0 on the bed.
- **Worn (renders):** `wear.standing()` turns the charm up: the front faces -y, y becomes z.

## Checks after any change

1. Run `uv run pytest` and `uv run ruff check`. The tests cover the font and the smallest font size (two measures), the layer grid, the M600 heights, the band order and nesting, raised strokes and open grooves, floating islands, valid single watertight solids, the volume of the slabs, the handle's orientation, the eyelet (balance, ring), the pockets (diameter, depth, roof, walls, positions, clearance), the counter plates and the pocket gauge, the clip (gap, slit, channel, walls, bar) and the clip gauge, the plates (bed fit, copies, start filament, M600s, bridges), the slicer checks with a fake PrusaSlicer, the renders and the command.
2. Run `uv run rh1charms export`. Every part must print `OK`. Compare the volumes with the previous run.
3. Run `uv run rh1charms render` and look at the images: `_flat.png` for the colours and letters, `_back.png` for pockets and clip, `_edge.png` for the bands and the channel, `_hang.png` for the balance (the mark on the centre of mass lies on the plumb line).
4. If PrusaSlicer is available, run `uv run rh1charms slice`: every plate must say `OK` (M600s, no support, bridges). Update the times and grams in the README.
5. **At the end of every new implementation, run the `code-review` skill at level `xhigh`** (the owner's rule), fix the verified findings, and run steps 1–4 again.

## 3MF and PrusaSlicer notes (from 3d-linux)

- PrusaSlicer reads `Metadata/Prusa_Slicer_custom_gcode_per_print_z.xml` even from a 3MF without print settings. That is how the M600s travel with the plates. One `<code>` per change, one `<mode>`. PrusaSlicer 2.9 (multiple beds) writes a `custom_gcodes_per_print_z` element with a `bed_idx` attribute for bed 0, plus one for each other bed that has changes, and reads the bed from there (none means bed 0); it ignores `bed_idx` on `code` and `mode`. `export.py` writes one element, for bed 0.
- The CLI always keeps those colour changes. The GUI (2.9.6, `Plater::load_files`) takes them only when it loads the file's configuration: **File > Open project** (Ctrl+O), "Open as project" in the drag-and-drop dialog, and the config imports ("Import config only", File > Import > Import Config from project), which put the file's colour changes on the plate that is open. A 3MF without print settings that is dragged in, double-clicked or imported (Ctrl+I) loads as geometry only, without the colour changes. The projects in `out/3mf/projects/` have the print settings, so dragging them in shows the dialog, unless the owner turned it off: then PrusaSlicer repeats the saved choice. The README says how to open each kind of file.
- A plate opened with Ctrl+O becomes the current project: Ctrl+S overwrites it with a full project (config included). `slicer.make_project` replaces such a config instead of adding a second entry.
- PrusaSlicer ignores the object colours of a 3MF. It shows the layers before the first M600 in the filament profile's colour (orange for Prusament PETG). So `slicer.py` passes the plate's start filament (`plan.json`) with `--filament-colour`, and the project carries it. The GUI marks the filament preset as "(modified)": that is expected.
- The CLI crashes on `--export-3mf` without a display. So `slicer.py` slices to text G-code, copies the `; prusaslicer_config` block into `Metadata/Slic3r_PE.config` and sets `binary_gcode = 1` again.
- The MK4 profiles build supports only inside support enforcers. `slicer.py` slices once more with `--support-material --support-material-auto --dont-support-bridges`; the result must have no support. That probe ignores bridges, so `slice` also checks that every height in `plan.json`'s `bridges` prints `;TYPE:Bridge infill`.
- The probe also passes `--raft-first-layer-expansion 0`. The profile widens the first layer of every support by 3 mm; under a free edge of the clip channel's ceiling (the two-line tag) the support generator trimmed its column to nothing, but the widened first layer stayed as a pad on the bed that supports nothing. A real column still prints its first layer without the widening.

## build123d gotchas

- **Always pass `dir=(0, 0, 1)` when you extrude a face**, and keep the outlines counter-clockwise (`relief._faces`): a clockwise face extrudes downwards.
- `Wire.make_polygon` cannot close a ring with near-duplicate points: `relief._wire()` drops them.
- **Micro-edges.** Every corner lies on `GRID` (1 µm, `_faces` rounds with `shapely.set_precision`), and band k's solid is `k * INSET` (2 µm per band) inside the band's edge, so a band's edge never touches the edge of the band below.
- `slab()` returns one solid per polygon, collected in a compound, with no boolean; `fuse()` joins all the bands in one go.
- `layout`, `band_parts`, `make_charm`, `make_counter`, `make_gauge` and `make_clip_gauge` are cached (`functools.cache`, keyed by the frozen `Charm`). Never change a returned part in place; transform it (`Pos(...) * part`) or combine it. `Shape.clean()` works in place: copy a cached part first.
- Once OCP is loaded, Python's default text encoding can become ASCII. Always pass `encoding="utf-8"` to `read_text`/`write_text`.
